# Decisions

- Phase 0 — Use the planned `patramail/` directory as the repository root so the supplied project plan stays outside the package.
- Phase 0 — Track this decision log and the npm lockfile for request traceability and reproducible development installs.
- Phase 0 — Use a local Git repository because GitHub CLI has no authenticated account in this environment.
- Phase 0 — Start at version 0.0.0 so Phase 8 can explicitly bump to 0.1.0.
- Phase 0 — Use the package manifest's `files` allowlist in place of `.npmignore`, as the plan permits.
- Phase 0 — Use ESLint 8.57.1 for development on all Node 18 minor versions; it is end-of-life.
- Phase 0 — Use Sarthak Gupta as the commit display name because the configured name contains pasted command text.
- Phase 1 — Accept absolute HTTP(S), mailto and tel links, and HTTP(S) logos only, to keep active URL schemes out of generated HTML.
- Phase 1 — Size logos at 160 × 48 with the product name as alt text because the draft has no image dimensions.
- Phase 1 — Support footer.address as optional text because the project structure calls for an address.
- Phase 1 — Use environment variable UPDATE_SNAPSHOTS=1 for deliberate snapshot updates across supported Node versions.
- Phase 2 — Accept only hex colors, unquoted system font lists and bounded integer pixel radii so theme CSS can be interpolated safely.
- Phase 2 — Apply automatic dark styling only to the named default theme so explicit dark and custom palettes retain their selected colors.
- Phase 2 — Choose black or white button text from the brand color's luminance so button text reaches 4.5:1 contrast.
- Phase 3 — Use first-seen row keys as table headings, string or finite number cells, and a matching optional total object so sparse receipt rows work.
- Phase 3 — Accept whole-number column widths of 1–100% or 1–999px to prevent CSS injection.
- Phase 3 — Place the table and one trusted body.unsafeHtml string before the outro so the draft schema can express totals and rich blocks.
- Phase 4 — Omit body.unsafeHtml from plain text because it contains HTML markup; use normal body fields for content both formats need.
- Phase 4 — Preserve the subject and preheader as transport metadata, returning undefined when omitted.
- Phase 4 — Use labeled table fields and blank lines between text sections for readability without column alignment.
- Phase 5 — Validate constructor product defaults merged with per-email product fields, with per-email fields taking precedence.
- Phase 5 — Treat NODE_ENV values other than production as development, report unknown keys there, and warn on subjects longer than 78 Unicode code points in every environment.
- Phase 5 — Return validation diagnostics from validate(), throw TypeError on invalid generation input, and emit nonfatal generation warnings through Node.
- Phase 5 — Canonicalize language tags and fall back to English for missing labels because only English ships in v0.1.0.
- Phase 5 — Add the runnable examples before the documentation phase because the preview script needs their inputs, and use an in-memory Nodemailer transport by default so the optional example can run locally.
- Phase 6 — Use Node 18 and 22 locally, Chrome for layout, and Ethereal for synthetic SMTP delivery because no hosted CI, target inboxes, or client-rendering service account was available.
- Phase 6 — Require explicit HTTP(S) authority syntax and a non-empty contact link target because URL parsers also accept forms that can resolve differently in HTML.
- Phase 7 — Add docs/password-reset.png to show a reviewed browser capture in the README.
- Phase 8 — Keep publishing and the GitHub tag and release manual so the user controls when the package goes live.
- Phase 8 — Treat package.json as mandatory npm metadata alongside src, README.md, and LICENSE in the packed artifact.
- Phase 8 — Install the tarball into an empty directory for the release smoke test because registry installation requires publication.
- Phase 8 — Use a temporary npm cache for packing because the managed workspace cannot write to the default home cache.

- Event template follow-up — Add six lifecycle templates as builders returning standard PatraMail inputs so callers can customize them and reuse the HTML and text API.
- Event template follow-up — Add src/events.js, src/sections/event.js, examples/events.js, docs/events.md and test/events.test.js for the preset catalog, rendered event card, examples, contract and regression coverage.
- Event template follow-up — Add src/mailgen.js and test/mailgen.test.js for a named compatibility adapter that keeps the original PatraMail return types and supports the documented Mailgen action workflow.
- Event template follow-up — Keep event names, dates and locations user-supplied, format dates as provided, and use English preset copy because the package ships only English labels.
- Mailgen-style follow-up — Make the Mailgen-style constructor the default CommonJS export so callers can switch the package name and keep their generation calls. Keep combined output under the named PatraMail export.
- Mailgen-style follow-up — Add examples/mailgen-style/index.js as a standalone caller example that writes its own preview file, separate from the structured fixtures used by npm run preview.
